# 高保真单文件原型设计准则（可点·可改·数值自洽的 UI 事实源）

## 1. 元信息

| 项 | 值 |
|---|---|
| 编号前缀 | HG-（A 流程门 / B 结构形态 / C 视觉令牌 / D 交互规范 / E 数据联动 / F 校验验收） |
| 适用 | 需要「产品负责人逐屏验收 → 再进工程实现」的 App/网页项目；UI 事实源先行、多模块/多 AI 会话并行深化 |
| 技术基线 | 单 HTML 文件 · Tailwind CDN + 原生 JS · 零构建零后端 · 桌面演示壳（手机外框） |
| 配套工具 | `checkjs.js` 内联脚本语法自检 · 无头 Chrome 深链截图 · 浏览器 DOM 断言 |
| 来源 | LifeHarness（2026-09，主原型 + 记账/书架/习惯/呵护/健康/同步等 10+ 模块专版实战沉淀） |
| 成熟度 | ✅ 已落地并验证（14 屏专版全链路断言 + 多轮逐屏验收迭代） |
| 版本 | V1.1（2026-09-25 增 HG-B8 反壳化三判据 + A3/B1 消歧；V1.0 初版） |

## 2. 一句话定义

> **高保真原型 = 一个双击即开的单 HTML，把全部屏幕与弹层做到「可点、可改、可回退、数值自洽」，作为工程实现前唯一的 UI 事实源与验收载体。**

## 3. 编号规则

### A · 流程门（原型与工程的权责关系）

| 编号 | 规则 | 为什么 |
|---|---|---|
| HG-A1 | **原型先行**：涉及 UI 的需求调整，先改原型、经确认后才升需求版本进入开发；禁止跳门直接编码 | 原型是唯一事实源；先码后画必然双向漂移 |
| HG-A2 | **双向保真**：开发对齐原型（逐屏核对），需求变更回流原型；实现与原型的「有意保留差异」必须成清单登记 | 无差异清单时，验收会把有意差异当 bug 反复返工 |
| HG-A3 | **专版文件模式**：模块深化=从主原型复制独立文件 `index-<module>.html`，**每文件单一写者**；主原型是共享面（壳层/底栏池/主页卡/全局弹层风格）唯一写者，副本要改共享面只登记「变更单」（位置/改什么/期望文案），由收口人统一回灌。**注意：专版是模块的深化副本，不是业务屏的唯一载体——主原型自身必须同时保有各模块的业务主流程屏（见 HG-B8）；「唯一写者」约束的是写权，不是内容归属** | 多会话并行改同一单文件 SPA 必撞车；变更单让共享面改动全程可追溯 |
| HG-A4 | **能力一次规划**：单模块专版按全量能力设计，不留「V1.x 后置/灰态占位」尾巴；确需延后必须显式拍板登记，而不是放个禁用卡 | 灰态占位会把范围欠账静默带入开发排期 |
| HG-A5 | **验收批次化**：逐屏反馈按「轮 N · 修订 M 条」成批落地，每轮全量过校验链后提交；需求文档/变更日志同批登记 | 零散改原型无法回归，接手人无从对账 |
| HG-A6 | **交接双模板**：设计会话产出「高保真 + 修订四件套」（原型/能力表/逐元素操作逻辑总表/口径规范）；开发会话开场白按五段模板引用事实源路径 | 让「把文档丢给 AI 就能开工」成立 |

### B · 结构与形态（单文件 SPA 骨架）

| 编号 | 规则 | 为什么 |
|---|---|---|
| HG-B1 | 一个 HTML 装下全部：手机壳+状态栏、顶栏（标题/副题/返回/上下文按钮）、`<main>` 内 N 个 `<section class="page">`、底部导航、FAB、全局弹层、`<script>` 内数据+路由+渲染器。**主原型是「完整可玩的 App 模拟」，不是壳/组件库/跳转页** | 双击即开、整包可拷贝分发、零环境依赖；打开即能走业务，验收不必在多个文件间跳转 |
| HG-B2 | **路由模型**：`stack[] + setPage/navTo/goBack`；`TITLES` 表统一维护每屏标题副题；底栏页切换清栈 | 与真实 App Navigator 语义一致，开发可 1:1 映射路由表 |
| HG-B3 | **返回语义**：有栈逐级回退 → 栈尽回主页 → 主页二次返回=退出提醒；多选/编排态下返回先退该态 | 原型阶段就定义清楚 Android 返回键行为，避免开发期临时发明 |
| HG-B4 | 底栏为**可配置栏目池**（固定项+开关项+数量上限），非写死 | 底栏配置本身是需求点，原型即演示其交互 |
| HG-B5 | FAB/顶栏按钮随上下文变化（`FAB_CFG[page]`），无添加能力的页面自动隐藏 | 减少「原型里有、开发忘了」的隐性需求 |
| HG-B6 | 弹层统一 `.sheet`（底部滑出+遮罩点击关+Esc 关），叠加层级定死（如 z70/z80） | 弹层叠加顺序是高频缺陷点，先立规矩 |
| HG-B7 | 每屏**深链**：`#p-xxx` 直达；详情/编辑屏支持 `#p-xxx_iN` 预选数据项；boot 时按 hash/search 自动 setPage+调渲染器 | 逐屏验收、无头截图、缺陷复现都靠直达，不靠人肉点过去 |
| HG-B8 | **主原型完整性（反壳化）三条判据**：① 从主页出发，每个模块的核心业务主流程（列表→详情→新建→编辑→删除/状态变更）都能在**本文件内点击走完**，不依赖跳转其它文件；② 主页入口卡点进去是**业务屏**，不是「专版未开」提示——模块专版未产出时，主原型里也要有该模块的基线屏；③ 组件词典/令牌预览/壳层自检等"设计系统页"只允许作为**辅助屏**（挂设置或独立入口），主页首屏必须是真实 App 的信息架构 | 真实事故（InputTrace 项目 2026-09-25 反馈）：按本准则生成的"主原型"做成壳+模块跳转页，业务屏全在专版文件里，主原型点开全是"未开"死链，完全无法演示操作逻辑——根因是把 HG-A3「共享面唯一写者」误读为「主原型只放共享面」 |

### C · 视觉与主题令牌

| 编号 | 规则 | 为什么 |
|---|---|---|
| HG-C1 | **三层令牌**：CSS 变量（--accent/--page/--card/--card-r/--card-sh…）→ 组件类（.card/.chip/.toggle…）→ 页面；颜色圆角阴影一律走变量 | 换肤=改变量表一处生效；工程侧同构为 ThemeExtension/令牌 json |
| HG-C2 | 主题=配置：内置多套主题 + 令牌 json 三方同构（原型 data / themes/*.json / App 资产），热切换、深色独立叠加 | 主题市场/外观设置等需求可在原型阶段直接验证 |
| HG-C3 | **图标口径先拍板**：全项目统一「线性 SVG」或「emoji」之一；主原型基线是什么，专版延续什么；变更整批处理并登记 | 混用是最高频视觉差评；单点替换反而制造不一致 |
| HG-C4 | UI 文案只留功能标签与状态提示，**不写教学性说明**；解释性内容放交付文档 | 交互靠自发探索；教学文案让界面变「说明书」 |
| HG-C5 | 组件复用先建**词典**（编号+中文名+锚点），微调指令按「编号 调整项」下达；新组件先登记再使用 | 产品与开发/AI 的寻址成本从描述性猜测降为引用编号 |
| HG-C6 | 细节口径进组件类：no-scrollbar、卡片密度、字号阶梯 | 高保真的「保真」一半在像素级习惯上 |

### D · 交互规范（可直接抄的行为）

| 编号 | 规则 | 为什么 |
|---|---|---|
| HG-D1 | 时间/数值选择**一律就地内嵌滚轮**（scroll-snap 真滑动+吸中+桌面拖拽）；禁止「点击→弹层→再操作」两段式与点选模拟滚轮 | 两段式被产品负责人两次否决后定型；滚轮组件全局唯一实现 |
| HG-D2 | 破坏性操作**二次确认**（首次点击变文案+警示，或 confirm），并保留审计时间轴（仅追加不删除） | 删除/冻结类操作口径必须在原型钉死 |
| HG-D3 | 配置类弹层=**固定预览区+草稿态**：预览不随列表滚动；选择只写草稿，「保存」生效、「取消」丢弃 | 所见即所得+可反悔的成熟范式 |
| HG-D4 | 选择态强区分：选中=品牌色描边+底色+「已选」标记；未选=灰描边+「点选」 | 仅文字变色的弱提示曾被验收打回 |
| HG-D5 | 状态机闭环：归档↔恢复彻底删除、逾期→去处理、多选态返回先退多选——每个状态都有入口和出口 | 单向左置状态会把异常留给开发猜 |
| HG-D6 | 空态给引导文案+动作按钮（如「新建 / 复制上期」） | 空态是转化点，也是能力完整性的展示位 |
| HG-D7 | 所有可点元素必有反馈（toast 复述结果+联动去向），toast 全局统一样式 | 静默交互无法验收「对不对」，也无法演示联动 |

### E · 数据模型与模块联动

| 编号 | 规则 | 为什么 |
|---|---|---|
| HG-E1 | 全局单一数据对象 `D`（+独立常量表），**渲染器只从数据实算**：合计、占比、进度、倒计时禁止手写与公式矛盾的假数字 | 演示值与引擎打架会被逐条戳穿（真实教训：手填日均 ¥1.22 与直线法实算 ¥18.98 矛盾） |
| HG-E2 | 交互改数据→重渲染→跳联动页，形成可玩闭环（付费→日均回升、勾选→生成待办、Try→下季草稿） | 原型价值在演示「行为」，不是截图 |
| HG-E3 | 跨模块联动统一「联动 L\<n\>」话术+去向说明，并在数据上真实挂来源徽标/引用 | 「非孤岛」是核心价值主张，联动必须可见可点 |
| HG-E4 | 模拟数据要有故事（时间轴事件/历史记录/归档周期），覆盖边界态：逾期/闲置/超上限/空周期 | 边界态数据齐了，开发不用自己编用例 |
| HG-E5 | 全局能力（搜索/备份/主题）在专版里保持可演示：搜索范围跟随当前模块，全局搜索库登记各模块代表条目 | 防止「专版只深模块、全局能力失活」的假完整 |

### F · 校验与验收（每轮必跑）

| 编号 | 规则 | 为什么 |
|---|---|---|
| HG-F1 | **语法门**：提取内联 `<script>` 逐块 `new Function` 检查；报错用 `vm.Script({filename})` 拿行号+原文定位 | 单文件里一个括号错=整页白屏；new Function 只给 "Invalid token" 定位极慢 |
| HG-F2 | **逐屏 DOM 断言**：setPage 全页面，检查 ①无 `undefined/NaN/[object ` 文本 ②**类名泄漏检测**（元素直接子文本节点匹配 `(^|\s)(ring-\|bg-\|text-(slate\|…)\|dark:)`）③渲染长度>阈值 | 语法全绿≠渲染正确；裸露类名是模板字符串高发事故 |
| HG-F3 | **截图目检**：无头 Chrome `--headless=new --virtual-time-budget=7000 --screenshot=<绝对路径>` 逐深链连拍，人工看语义配色与溢出 | 截图能抓到断言抓不到的缺陷（配色反了、裁切、重叠） |
| HG-F4 | **交互回归**：一轮 evaluate 串关键链路（增删改→联动→回退），断言数值变化而非仅「没报错」 | 防「改 A 坏 B」；也是「已验证」的证据 |
| HG-F5 | 长任务校验实时可见：不接 `| tail` 缓冲；批量改源码用脚本文件而非 heredoc | 无输出等待=不可观察；heredoc 静默断裂最难查 |
| HG-F6 | 浏览器面板隐藏时截图报错 `NATIVE_BROWSER_VIEWPORT_UNAVAILABLE`：DOM 断言仍可做，截图降级交用户本地或切无头；隐藏页 rAF 挂起、setTimeout 节流，断言前显式调渲染函数 | 别把环境限制当代码 bug 反复改 |

## 5. 验收清单（交付前逐项打勾）

- [ ] 双击打开即主原型首页；多主题×深浅色无破版；底栏/FAB/顶栏按钮随屏正确
- [ ] **反壳化三判据（HG-B8）**：从主页可走完每个模块的业务主流程且全程不跳文件；入口卡点开是业务屏不是"专版未开"；设计系统页仅居辅助位
- [ ] 每模块：列表→详情→编辑→保存→回列表可见变化；返回键全程可退；无死胡同状态
- [ ] 全部数值由引擎实算且互相一致（hero=Σ明细、进度=cur/tgt、倒计时=日期差）
- [ ] 边界态可演示：逾期/空周期/上限拦截/归档恢复/多选退场
- [ ] 联动去向可点（转待办→待办屏、来源徽标→来源模块）
- [ ] checkjs 全绿；逐屏断言无 `undefined/NaN/[object`、类名泄漏=0；深链每屏可达
- [ ] 关键链路交互回归通过（改数据→重渲染→联动页）
- [ ] 逐屏截图归档（`shots/<module>/`），与缺陷登记一并交付
- [ ] 需求文档/变更日志同批登记（版本号+事实源路径+决策口径）
- [ ] 共享面改动以变更单存在，未在副本内擅自定稿

## 6. 已知坑

| 坑 | 根因 / 处置 |
|---|---|
| 页面裸露 `ring-1 bg-slate…` 一串字符 | 模板字符串把状态类名写到 `>` 之后而非 `class="…"` 里；语法/id 断言全绿也发现不了 → 必跑 HG-F2 泄漏检测 |
| 整页白屏但语法检查通过 | 顶层 `const top/name/length/status/origin/screen` 与 window 全局冲突，内联脚本静默失败 → 命名避开；用 `vm.Script` 拿行号 |
| Tailwind `hidden` 与 `grid` 同元素不生效 | 同为 display 工具类，声明顺序不可靠 → 外层包只挂 `hidden` 的 wrapper |
| 隐藏页断言假阴性（元素"不存在"） | 浏览器面板 hidden 时 rAF 挂起、setTimeout 节流、截图直接报错 → 断言前显式调渲染函数；截图切无头 Chrome |
| 深链 `#p-xxx` 二次导航不生效 | hash-only 变化不触发 boot（同文档导航）→ 验收用完整 reload 或无头新实例 |
| 正则取深链把 `_i2` 参数吞进页面 id | `\w` 含下划线 → id 字符集写 `[A-Za-z][A-Za-z0-9]*`，参数段单独捕获 |
| 演示数值与公式打架 | 手填"好看"数字与引擎矛盾 → 一切展示数走渲染器实算（HG-E1） |
| 批量替换截断引号/多行字符串 | shell heredoc 与中文引号转义吞字符 → 用独立脚本文件（python/node）改，跑完必 checkjs |
| grep 结果被 base64 长行淹没 | 内嵌 dataURI 命中一切关键词 → 先 `awk 'length($0)<400'` 过滤长行 |
| 灰态「V1.x 占位」卡混进专版 | 范围欠账被视觉合法化 → 能力一次规划（HG-A4）；确属他模块的卡直接移除并注明归属 |
| 多会话同改一份原型互相覆盖 | 单文件无合并语义 → 专版单写者+共享面变更单（HG-A3） |
| 主原型被做成"壳+跳转页"，点开全是"专版未开" | 「共享面唯一写者」被误读为「主原型只放共享面」→ 反壳化三判据 HG-B8：业务主流程必须能在主原型内走完 |
| 验收返工「改了 A 坏了 B」 | 只验改动屏 → 每轮全量跑 F1~F4 再提交（HG-A5） |
| 中文提交信息/文档在终端乱码 | Windows 控制台编码显示问题，非内容损坏 → 以文件内容为准复核，勿盲目重写 |
| 两段式选择器被打回 | 「点击→弹层→再操作」被产品负责人两次否决 → 时间/数值一律就地滚轮（HG-D1） |

## 7. 复用清单（什么场景用哪条）

| 场景 | 直接引用 |
|---|---|
| 新项目启动、只有一句话需求 | B/C/D 全组 + 实现骨架，半天可出主原型 |

| 产品负责人逐屏验收流程设计 | HG-A1/A2/A5、HG-D3/D4、验收清单 |
| 主题换肤/深色需求 | HG-C1/C2（三层令牌+json 同构） |
| 表单/选择器交互被吐槽 | HG-D1（内嵌滚轮）、HG-D3（草稿保存制）、HG-D4（强选中态） |
| 原型「看起来假」 | HG-E1（实算引擎）、HG-E2（联动闭环）、HG-E4（有故事的边界数据） |
| 自动化自检脚本编写 | HG-F1~F6 + 已知坑表当 checklist |

# 【模块注册表 + 屏单一归属 + 分级定位回执】多模块产品的原型-代码一致性治理（可复用）

| 项 | 值 |
|---|---|
| 标签 | `AI协作` `流程治理` `原型` `模块化` `守护门禁` |
| 成熟度 | 已落地（规则与文档口径已生效并双端推送；`pfind`/注册表/闸在下一批实现） |
| 来源项目 | LifeHarness（Flutter + sqflite 个人管理 App，18 模块）· `docs/handoff/交棒话术-20261003-原型瘦身与屏单一归属治理.md`、`AGENTS.md` |
| 参考实现 | 注册表 `_modules.json`（待建）· 定位器 `pfind.js`（待建）· 死链与五检 `tools/doclint.py` · 架构闸 `test/architecture_test.dart` |
| 适配成本 | **低**（≤5 模块的项目只取"注册表 + 双向归属闸"即可）／**中**（要自然语言与截图定位，需别名表＋切片工具；多会话并行需冻结窗口） |

> 解决什么问题：多模块产品里，同一张界面在多个原型文件、多份代码里各存一份副本，于是"改一处要改 N 处、
> 下架改不干净、AI 会话每次都靠全文检索猜位置、产品说人话而工具只认编号"。
> 方案＝**一张屏只有一个家 + 一份机器可读的模块注册表 + 把自然语言/截图解析成定位四元组 + 分级回执 + 四道闸**。
> 不适用：单页/单模块小工具（成本大于收益）；也没有原型与代码两套产物的纯后端项目（只取 §4.3 的"下架反向清单"即可）。

---

## 0. 一句话定义

把"哪个功能在哪个文件的哪一段、改了会连带影响谁、下架要清哪几处"从**人的记忆**变成**一张注册表 + 四道自动闸**，
并规定 AI/开发者收到自然语言或截图时**先解析定位、再按代价分级决定是否停下确认**。

## 1. 术语

| 术语 | 说明 |
|---|---|
| 屏 / 弹层 | 可独立验收的界面单元；弹层、抽屉、二级弹窗与屏同级，**不能只统计整屏** |
| 家（归属） | 这张屏的**唯一定稿副本**所在文件；别处只允许代表屏或占位屏 |
| 代表屏 | 模块在"全局壳文件"里保留的一张主屏，用于跨模块流转演示 |
| 占位屏 | 别处的一行桩（写明"本模块细节见 X 文件"），或干脆不留、由导航兜底 toast |
| 注册表 | 机器读的模块台账（`_modules.json`），**唯一驱动源**；人读表由它生成 |
| 别名 aliases | 每个模块/屏/组件的"人话叫法"（"记账那页""日历格子"），自然语言与截图定位靠它 |
| 定位四元组 | 解析产物 `{模块, 屏/弹层, 组件, 意图}`；意图＝新增能力/微调/下架/缺陷 |
| 定位卡 | 动手前的回执；**上半给人看（人话＋圈红截图），下半留档（锚点）** |
| L0/L1/L2 | 回执分级：直接开工 / 摘要不阻塞 / 必须停下等确认 |
| 幽灵入口 | 功能已下架但路由、底栏、设置行、DB 表或守护白名单里还留着残留 |

## 2. 需求规则（编号即验收项）

**归属与注册表**
- **R1 一张屏只有一个家**。理由：两份副本＝迟早漂移，漂移后没人敢说哪份是真的。
- **R2 注册表是唯一驱动源，JSON 为源、md 表为产物，禁止手改产物**。理由：两份都可编辑就必然分叉。
- **R3 每个模块/屏/组件的 `aliases` 必填非空**。理由：没有别名表，自然语言与截图就退化成关键词口令。
- **R4 新增屏必须同批登记归属，否则闸红**。理由：不登记的模块会在下一次"整包复制"里复活。
- **R5 历史/延后产物必须标 `status: frozen/deferred` 且禁止当现行事实源回灌**。理由：误当现行是返工的最大来源。

**定位与回执**
- **R6 任何 UI/功能指令先解析四元组，再动手；解析不出或多义必须先问，不许猜**。理由：改错对象的返工成本远高于一次提问。
- **R7 回执分级，判定句＝"改错对象的代价 ≤ 一次 `git revert` 就直接往下走；代价是丢数据、丢功能或返工一整批才先问"**。
  理由：把确认做成"每步都等"会让流程贵到被绕过，规则反而失效。
- **R8 给人看的回执禁止出现 id／行号／类名／函数名；连带影响必须翻译成功能语言**（"这两屏会一起变"）。
  理由：产品负责人核对的是"你找没找对地方"，不是坐标。
- **R9 截图按需生成、默认不自读、一批一卡**。理由：本方案要省的是读取成本，不能自己变成新的成本源。
- **R10 入口不做关键词口令**（自然语言与截图是主输入）；只有"流程状态切换"（开工/收尾/发布）才用短口令。
  理由：人说话不带编号，靠口令触发的规则覆盖率上不去。

**下架与整改**
- **R11 下架必须清六处**（原型屏与弹层／注册表行标 dropped／需求条目移入修订史／路由与入口／DB 表处置／能力点与守护白名单）。
  理由：漏任一处就是幽灵入口，而下一次会话会照着幽灵入口把功能"复原"。
- **R12 已撤销能力进"勿复活清单"，并被闸扫描**。理由：本项目三次踩坑（工具集、影音模块、第三方书源）。
- **R13 删副本前先做漂移比对**（同 id 逐份 diff）。理由：**"删除"其实是"合并后删除"**，直接删会丢某份独有的后加功能。
- **R14 删屏必须连带删逻辑**（以保留屏集合为根做可达性分析）。理由：只删 markup 体积不降，还留下死代码更难读。
- **R15 治理动作要单开冻结窗口**，期间其他会话不动被治文件。理由：并行会话会按旧副本把删掉的东西写回来。
- **R16 规矩必须配闸；无闸的规矩要显式标注为"自觉项"**。理由：假装是硬闸比承认管不住更危险。

## 3. 状态机 / 数据模型

注册表一条记录（模块级，屏级为其数组）：

```jsonc
{
  "id": "ledger", "name": "记账", "req": "V1.32~V1.40",
  "proto": "prototype/index-ledger.html",
  "status": "active",              // active | deferred | dropped | frozen
  "entries": { "tabbar": false, "settingsRow": true, "deepLink": "?brNN=" },
  "routes": ["/ledger"], "dbTables": ["bill", "bill_tag", "merchant"],
  "schemaRange": "v12..v20", "aiTasks": ["ledger.ocr"],
  "ticket": "docs/handoff/xxx.md",
  "screens": [
    { "id": "p-billImport", "kind": "screen", "home": "prototype/index-ledger.html",
      "aliases": ["导入账单", "账单导入那页"], "proxyIn": { "index.html": "representative" },
      "checks": ["tools/br57check.js"], "tests": ["test/ledger_import_test.dart"] },
    { "id": "sheetBillPick", "kind": "sheet", "home": "prototype/index-ledger.html",
      "aliases": ["选账户那个弹层"] }
  ],
  "redirects": { "p-oldHome": "prototype/index-ledger.html#p-billImport" }
}
```

不变式：① 任意 `screens[].id` 全局只有一个 `home`；② `status=dropped` 的模块在 `lib/` 与现行原型里零命中；
③ `aliases` 非空；④ 文档引用的锚点必须能在 `home` 文件解析到，或存在于 `redirects`。

## 4. 关键流程（三个角度）

### 4.1 项目初始化：只有一次"零包袱"窗口

新模块第一天就把下面十二步走完，之后所有治理成本都接近零；漏掉任何一步，将来都要靠整改补：

1. 需求条目编号（进需求清单，不写实现细节）→ 2. **注册表建行**（含 aliases）→
3. 原型新建，**从一开始就分片**：`prototype/<mod>/src/{shell.html, screens/*.html, tokens.css, app.js}` ＋ `build.js` 装配出可双击的单文件
（存量巨型单文件**不要拆**——迁移风险大于收益；只有新模块享受这个规则）→
4. 路由/底栏/设置行登记 → 5. DB 表与 schema 版本登记 → 6. 架构守护的白名单登记 →
7. 建活工单（批次规格唯一依据）→ 8. 建逐屏验收清单（深链锚点写进清单）→ 9. 状态源更新"下一站" →
10. 每屏截图基线（仓库外）→ 11. `pfind` 自测可查（查不到＝别名没填好，当场补）→ 12. 可选：方案库沉淀。

关键判断：**分片只用于新产物，单文件只用于存量**。反过来做（把存量拆成碎片）是这类治理最常见的翻车点。

### 4.2 后期维护：日常一次微调怎么走

```
产品输入（中文/截图/圈选/LH 号/深链）
   └─ 解析四元组 {模块, 屏/弹层, 组件, 意图}      ← 注册表 aliases + pfind
        ├─ 失败或多义 → 发 2~3 张候选截图请对方圈（不许猜）
        └─ 成功 → 判级：
             L0 目标唯一、只碰一屏 → 回一行摘要 → 直接开工
             L1 跨屏/共用组件     → 回摘要（含"这两处会一起变"）→ 不阻塞，做完一起收口
             L2 视觉分歧 / 不可逆 / 定位不确定 → 圈红截图 → 停下等确认
   └─ 动手：原型先行 →（L2 才）逐屏确认 → 实现 → 该模块 check 回归 → 状态源与工单同步
```

截图定位三档：图内有可读文案 → 按文案反查屏；只有形态 → 对照组件词典；都不中 → 现截同屏比对。
**三档全失败就明说定位不到**，宁可多问一句，不要"看起来像"就改。

### 4.3 整改：存量项目已经烂了怎么办

顺序不能换（先有表 → 再删 → 再上闸），否则边删边被写回：

0. 拍基线快照 ＋ 记录各校验脚本**当前**红绿（存量红不许代修，也不许算进本批回归）。
1. **漂移比对**（§R13）→ 出"有实质差异的副本清单"，交产品勾定归属。
2. 注册表定稿（含屏/弹层全量登记）＋ 每屏截图基线。此步**只报警不删**。
3. **上闸**（§7 四道）＋ 变异自证（塞一个假屏必须红，否则闸是空的）。
4. 动全局壳文件：一次一个模块，删前后同深链截图比对 ＋ 控制台零 error。
5. 逐份模块文件动刀（同一验证）。
6. 读侧工具收口（切片器/索引卡），量化"改一屏的读取成本"。
7. 规则三处同步（入口指南 / 计划书 / 组件规范），状态源与变更日志收口。

度量线（缺一不算完）：单文件目标体积、总字符降幅、**改一屏典型读取 ≤ 4k token**、
校验脚本相对基线零新增红、深链可用率 100%（含重定向）、死函数计数 0、同 id 全局唯一副本、新闸变异自证通过。

## 5. 与数据层的边界规则

- **D1 模块与 DB 表必须在注册表里成对登记**，下架时按"表处置三问"作答：表保留还是 DROP／历史数据归档到哪／同名入口是否清。
- **D2 改写出端格式必须同批改反解端**（导出格式变了，解析端不改＝静默丢数据）；配 round-trip 断言。
- **D3 缓存/分页表若其"语义输入"变了必须升版本号**，否则旧缓存命中＝真机假生效。
- **D4 迁移脚本要覆盖"起始版本"而非只测最新版本**（升级路径的坑几乎都在起始版本 key 上）。

## 6. 性能规则（这里的"性能"＝上下文与人力成本）

- **P1 禁止整读巨型产物文件**（原型/生成物/大 JSON）；一律切片读。实测单文件 0.5–1.0MB ≈ 16–29 万 token，整读必然被截断且不可靠。
- **P2 定位靠表不靠检索**：`pfind` 一次命中替代 3–5 次全文 grep ＋ 数百行阅读。
- **P3 回执成本要低于它防的返工**：一次改错对象的回滚＋重做 ≫ 十次定位卡。
- **P4 截图与图片按需**：只有 L2 或自证需要才生成/读取（视觉 token 单价最高）。
- **P5 门禁链必须短路**：验证段用 `&&` 前置或显式 `exit`，禁止 `gate; ...; commit` 这种写法（rc 会被后续命令覆盖，红灯照样提交）。

## 7. 扩展点

- **E1 多 agent 并行**：注册表的 `home` 字段天然就是写权边界，可直接当互斥面用；配合"冻结窗口"避免互相覆盖。
- **E2 CI 化**：四道闸都是纯静态检查，适合放 PR 前置；变异自证用例（塞假屏必红）也要进 CI，防闸空转。
- **E3 设计令牌同源**：原型 `:root` 变量与代码主题令牌共用一份（改一处两边生效），深色模式与主题正交组合。
- **E4 跨端**：注册表与 `pfind` 与语言无关，只有"代码一致性闸"需按栈改实现（目录约定/路由表/表清单）。
- **E5 反向用途**：注册表可直接生成"模块清单页""设置入口列表""备份范围白名单"等运行时配置，避免配置漂移。

## 8. 实现骨架

```js
// pfind.js —— 把任意输入解析成定位四元组
pfind(query) -> {
  module, screen, component,           // 解析结果（含置信度）
  file, lines: [start, end],           // 唯一定稿副本位置
  relatedFns: [...], relatedClasses: [...],
  sharedBy: [{file, why}],             // 连带影响（给人看时翻译成功能语言）
  checks: [...], tests: [...]          // 该屏的回归入口
}
// 入口形态：中文别名 | "LH-12" | "#p-xxx" | "?brNN=" | --text "截图里的文案" | --shot x.png [--box x,y,w,h]
// 查不到 id / aliases 为空 → 直接报错（防注册表空心化）

// 四道闸（挂在文档/测试的静态检查里）
gate1 双向归属：moduleFile 含他模块屏 → 红；shellFile 含"home≠此"的细节屏 → 红；未登记 section/sheet id → 红
gate2 注册表↔代码：status=active 必须有代码目录与路由；status=dropped 不得在源码或入口配置里残留
gate3 勿复活：修订史中已撤销的模块/能力名出现在现行源码或原型 → 红
gate4 别名非空：任一模块/屏/组件 aliases 为空 → 红
// 每条闸都要配变异自证用例；无法机检的纪律（如"回执是否真给人看"）在文档里标注为自觉项
```

## 9. 验收用例清单

- [ ] 注册表 JSON 为源，人读表由脚本生成；手改产物文件会被闸拦下
- [ ] 每个模块/屏/组件 `aliases` 非空；清空一条后闸红
- [ ] 模块文件里塞一张他模块的屏 → 归属闸红；删掉后绿
- [ ] 把某模块标 `dropped` 但留一个入口 → 一致性闸红
- [ ] 在需求修订史里已撤销的能力名出现在源码 → 勿复活闸红
- [ ] 用中文俗称（"记账那页"）能定位到唯一屏；用截图文案 `--text` 能反查到屏
- [ ] 定位多义时不猜测，返回候选并要求圈选
- [ ] L0 改动不产生等待（一行摘要后直接开工）；L2 改动会停下等确认
- [ ] 给人看的回执里不含 id/行号/类名（可用正则断言）
- [ ] 整改前已拍基线快照，且存量红已记录、未被本批"顺手修掉"
- [ ] 删副本前已出漂移比对报告；差异屏有"以哪份为准"的书面结论
- [ ] 删屏后死函数计数为 0，深链可用率 100%（含重定向表）
- [ ] 门禁链用 `&&`/显式 exit，红灯时不会走到提交与推送

## 10. 已知坑

| 现象 | 根因 |
|---|---|
| 删了副本，功能却少了东西 | **同 id 早已漂移**（实测同一屏在 8 份文件里有 3 个版本）；"删除"实为"合并后删除"，必须先 diff |
| 瘦完身体积几乎没降 | 只删了 markup，没删配套函数与演示数据（JS 常占文件 50–62%）；需可达性分析 |
| 统计说"重复 20%"，实际更多 | 只数了 `<section>`，**弹层/抽屉/二级弹窗没进账**；归属单位必须含 sheet |
| 文档悄悄指向空气 | 深链锚点被删，而死链守护只查文件存在不查锚点；需锚点校验＋重定向表 |
| 删掉的屏又回来了 | 并行会话按旧副本回灌；治理必须**单开冻结窗口** |
| 红灯状态下照样提交并推送了 | 门禁命令用 `;` 串在链首，rc 被后续 `echo` 覆盖；验证段必须 `&&` 前置或显式 exit |
| 死链守护把方案自己判红 | 引用**待新建**文件时写了完整路径形式（`tools/x.js`）；写"文件名（放 X 下）"才不触发 |

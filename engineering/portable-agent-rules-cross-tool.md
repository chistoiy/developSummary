> 解决「AI 规则、上下文、记忆**换个工具就丢、换台机器就读不到**」的可移植性问题。
> 适用：由 AI 代理开发、且**同时/先后使用多个工具**（WorkBuddy / Trae / Qoder / ZCode / Claude Code / opencode / Cursor / Codex…）的项目；含单人项目。

## 0. 一句话定义

把「AI 要遵守的规则 + 上下文 + 记忆」当成一套**规则系统**来设计：机器只认一份入口（`AGENTS.md`），其余工具用**只写指针**的别名接入；**能跟着仓库走的知识全部入 git，只在这台机器有用的进工具目录**；规则自带「只减不增」的体量棘轮与「必需小节」闸，防折叠丢失——于是换工具零配置、换机器 `git clone` 即用。

## 1. 术语

| 术语 | 说明 |
|---|---|
| 通用底座 / 单一事实源 | `AGENTS.md`：被 25+ 工具原生读取的入口文件，规则的**唯一定义处** |
| 别名件 | 只被某一工具读取的入口（如 `CLAUDE.md` / `.cursorrules`），正文**只写指针**，不写规则内容 |
| 第二规则目录 | 某工具的原生规则目录（`.qoder/rules/`、`.trae/rules/`、`.cursor/rules/`、`.clinerules`…），**优先级高于 `AGENTS.md`**，建了＝第二事实源 |
| 冷启动兜底 | 该工具首次未自动读到 `AGENTS.md` 时，用户补的一句「读 `AGENTS.md` 后说『开工』」 |
| 体量棘轮 | 入口/热点文档的**字节数或行数上限**，机制＝钉基线＋只减不增＋放宽须人审 |
| 必需锚点小节 | 入口文件里**必须存在的标题**（缺即 lint 红灯），专防「规则被折叠/合并后静默失效」 |
| 知识载体存活矩阵 | 按「换工具、换机器后是否还在」给知识分类，决定它该住 git 还是工具目录 |

## 2. 需求规则（编号即验收项）

- **R1 单一事实源**：所有规则**只在 `AGENTS.md` 定义一次**，其余任何文件（含别名件、README、计划文档）一律写指针。判定标准：全仓搜索某条规则的关键串，命中位置 ≤1 处为「定义」，其余为指针。
- **R2 入口必须自包含**：核心规则不能只放在被引用的文件里。**ZCode 不展开 `@import`、不合并嵌套、不扫子目录**——若把禁令写在 `AGENTS.md` 引用的另一份文件里，ZCode 读不到。判定标准：把 `AGENTS.md` 单独拷出来也能读全规则。
- **R3 禁建第二规则目录**：`.qoder/rules/`、`.trae/rules/`、`.devin/rules/`、`.cursor/rules/`、`.clinerules`、`.windsurfrules` **一律不建**——它们在各自工具里优先级高于 `AGENTS.md`，建了就是第二事实源（与 R1 冲突）。某工具确不认 `AGENTS.md` 时，只用**一枚只写指针的别名**接入。
- **R4 别名只写指针**：`CLAUDE.md` / `.cursorrules` 等正文只写「唯一事实源是 `AGENTS.md`」＋极少数不可让步口径（状态源在哪、文档路由在哪、门禁命令），**不写规则内容**。判定标准：别名件里找不到规则本体。
- **R5 体量双顶**：`AGENTS.md` 目标 **≤16 KB / ≤90 行**（依据：① Codex `project_doc_max_bytes` 默认 **32 KiB**，超则静默截断；② 每轮 prompt 都注入 ⇒ 直接是 token 成本）。
- **R6 知识载体存活矩阵**：**跟着仓库走的知识 → git**（规则进 `AGENTS.md`、经验坑进入仓笔记）；**只在这台机器有用的 → 工具目录**（会话流水等，gitignored）。判定标准：该知识在 `git clone` 到另一台机器后**是否还需要**——需要就必须入 git，不需要才留工具目录。
- **R7 入仓文档禁指工具本地路径**：git 跟踪的文档里**不得出现 `.workbuddy/` 等 gitignored 路径的活指针**（否则换机 clone 后照「必读清单」读会读不到）。判定标准：lint 扫全部入仓 md，出现 `\.workbuddy/` 即红灯。
- **R8 必需锚点小节齐全**：`AGENTS.md` 必须包含一组固定标题（示例：开工先读／工单生命周期／环境事实／验证门禁／禁令／忽略清单／会话口令／会话收尾仪式）。判定标准：标题缺失或被合并 ⇒ lint 红灯（专防「折叠丢失」）。
- **R9 体量棘轮**：入口、**热点文档**与**轻量索引件**（排期池一类）的体积**只减不增**，放宽须走人审并在规则里写理由。判定标准：入口 ≤16 KB／≤90 行（R5）、热点文档（交接/清单类）设字节与行数上限、索引件设「KiB＋行数」双顶——**字节与行数两道都要**（行数预算挡不住「一行滚到几万字符」，只有字节闸拦得住）；超顶即 lint 红灯（机制照抄色值棘轮／行数预算棘轮，见姊妹篇《棘轮式守护用例在多写者下的维护口径》）。
- **R10 跨工具口令复用**：会话口令（如「开工」/「收尾」）的**定义处唯一**（在 `AGENTS.md`），所有工具共用；不新造「工具专属开场白」。
- **R11 冷启动两档**：读得到 `AGENTS.md` 的工具＝**零对白**（直接说口令）；读不到的（Trae 需开开关 / Gemini CLI 需配 `context.fileName` / Claude Code 只认别名）＝首次补**一句**「读 `AGENTS.md`，然后说『开工』」。
- **R12 git 兜底**：规则系统的健壮性最终由版本控制提供——任何改坏可 `git revert`；别名件内容固定且短，可随 R8 同套断言校验。

## 3. 状态机 / 数据模型

知识的三个层次，按「跟随仓库的能力」划分：

```
git 仓库层（换工具/换机器都在）
  ├─ AGENTS.md            规则唯一定义处（≤16KB/≤90行 · 自包含）
  ├─ 别名件 CLAUDE.md/.cursorrules   只写指针
  └─ docs/
      ├─ STATUS.md        唯一状态源（本批/上一批两级）
      ├─ INDEX.md         文档地图（登记制，机器倒逼）
      ├─ handoff/         活工单（新工单唯一出生地）
      ├─ archive/         闭环归档（只进不出）
      └─ agent笔记/       经验坑入仓（docs 深度≥2 目录，天然豁免 INDEX 行数预算）
工具本地层（gitignored，换机器即消失）
  └─ .workbuddy/memory/YYYY-MM-DD.md 等   只放本机临时，不承载任何项目规则
```

不变式：
1. 任一时刻，每条规则**只有一份定义**（在 `AGENTS.md` 或它指向的入仓文件里）。
2. 入仓文档中**不含**指向工具本地层的活指针（R7）。
3. 别名件的有效负载**极短**（R4），且总是指向 `AGENTS.md`。

## 4. 关键算法或流程

**「这条知识该住哪」判定流程图**（三条互斥问句，自上而下）：

```
① 换工具 / 换机器后还需要它吗？
   ├─ 不需要 → 工具本地层（会话流水类）
   └─ 需要   → ② 它是「规则」还是「经验坑」？
                ├─ 规则   → AGENTS.md（若过长，拆到入仓的法规文件并留指针）
                └─ 经验坑 → 入仓笔记（docs 深度≥2 目录，豁免 INDEX 预算）
             ③ 它是「本批要做」还是「将来做」？
                ├─ 本批   → 写进 STATUS 的「下一站」行
                └─ 将来   → 写进「排期池」一行
```

**落点互斥**：同一件事同一时刻**只许出现在一处**——`STATUS 下一站` 与 `排期池` 互斥；工单开工当轮从排期池摘掉该行并在 STATUS 点名。这与代码侧「一张屏只有一个家」是同一套单一归属原则。
**⚠ 实测复发点**：规则写得再对，**入口文件若零提它，换个 agent 就丢**——判定句（「点名本轮开工 → 写 STATUS 下一站；其余凡采纳未排期／搁置／待定 → 排期池一行」）必须在入口文件里有一行指针，且在开工链（入口 → STATUS → 工单）上能被走到；否则「入口不可见」＝规则等于不存在。

## 5. 与数据层的边界规则

- **D1** 治理只动**文档、入口别名与校验脚本**，零代码/测试改动；全量测试基线不因治理轮重跑。
- **D2** 别名件内容固定且短 ⇒ 可作为 lint 断言对象（「只含指针」可机判）。
- **D3** 迁出工具本地层的知识时，先扫全仓引用（`grep -rn '\.workbuddy/'`），把所有「必读清单/开场白模板」里指向它的条目一起改到新家，否则迁了等于没迁（换机仍读不到）。

## 6. 性能规则

- **P1** 每会话注入成本 ≈ `AGENTS.md` 字节数 → 体积上限即读取成本上限（R5 的双顶就是性能闸）。
- **P2** 别名件每枚有效负载 ≤1 行 → 多接一枚工具的成本可忽略，不必为省 token 而放弃别名。
- **P3** 收益量化用两个数：入口必读**字节数**、`git clone` 后**可读规则覆盖率**（入仓规则数 / 规则总数，目标 100%）。

## 7. 扩展点

- **E1 新工具出现时**：只查一件事——「它是否原生读 `AGENTS.md`」？读 ⇒ 零动作；不读 ⇒ 加**一枚只写指针的别名**（R4）。不要为它另建规则目录（R3）。
- **E2 棘轮阈值**：随项目调整，但机制固定（钉基线＋只减不增＋放宽须人审）。
- **E3 经验坑家命名**：可用 `docs/agent笔记/经验坑.md`、`docs/notes/pitfalls.md` 等；关键是放**入仓且不挤 INDEX 行数预算**的目录（`docs/` 深度≥2 的子目录天然豁免顶层 INDEX 登记）。

## 9. 验收用例清单

## 10. 已知坑

| 现象 | 根因 |
|---|---|
| 换了 AI 工具后「规则丢了」 | 规则住在 **gitignored 的工具目录**（如 `.workbuddy/memory/MEMORY.md`）：不入仓 ⇒ 换机 clone 没有；无入口指针 ⇒ 新工具不知道它存在；闸看不见（lint 只扫入仓件）⇒ 三重失联。这是「换工具丢规则」的**结构性唯一根因** |
| 换机 clone 后照「开工必读清单」第 1 件却读不到 | 入仓文档里写着指向**不入仓路径**的活指针（把工具目录的记忆文件列为必读）。doclint 抓不到——它不在扫描集里 |
| 给 gitignored 文件上了体量棘轮，仍换工具即丢 | **守错对象**：对隔离仓上棘轮毫无意义。棘轮只该上在**入仓**的入口文件上 |
| 入口件自己打自己 | 同一文件两处口径（旧命令与新命令并存）／权威指针指向已腐化的细则文件。改口后**旧口径没删**，换 agent 时读到哪条看运气 |
| 行数闸全绿，注入却被截断 | 只数**行数**不数字节：入口靠**长行**撑到 16 KB 仍恒绿；而 Codex 默认 32 KiB 截断、每轮 prompt 真金白银。必须改数**字节数** |
| 把禁令写在被引用的文件里，某工具读不到 | ZCode **不展开 `@import`／不合并嵌套／不扫子目录** ⇒ 核心规则必须**自包含**在 `AGENTS.md` |
| 为「让某工具更懂」而新建了它自己的规则目录 | 该工具的原生规则目录**优先级高于 `AGENTS.md`** ⇒ 立刻造出第二事实源，两处口径迟早分叉 |
| 上棘轮后又反弹（二轮治理定的瘦身目标全部回退） | 没有常驻闸。对照看：**有闸的守住了、没闸的反弹了** ⇒ 治理的正确形态不是再写一轮方案，而是把结论变成**棘轮**（只减不增） |
| 闸报「死链」，可文档里那条路径明明是对的 | 路径正则把**紧邻的全角标点**吞进了路径串：`…/经验坑.md＋AGENTS.md` 里的全角 `＋` 不在终止字符集内，整串被当成一个文件名 ⇒ 误判死链。定式＝路径后接全角加号/顿号/书名号等，**必留空格或用反引号分隔**；写完先跑闸再交 |
| 守护刚写完就把自己的**说明文字**判红 | **守护条文自指**：注释/说明里原样写出被禁的路径串（如 `.workbuddy/`），扫描器分不清「讨论它」与「违规」。解法＝改文案回避，或给该行加豁免词（豁免表里写理由） |
| 新加的文档明明有违规，闸却是绿的 | lint 只扫 `git ls-files`（在库文件）⇒ **新增 md 没 `git add` 就不在扫描面**，是隐形盲区。规矩＝文档落盘后先 `git add` 再跑闸 |
| 索引件（排期池）一路涨到近百 KB 却没人拦 | 索引件初建时很轻，容易被当成「随手堆历史流水」的垃圾桶（本项目实测 93.7% 是迁入的历史流水表）⇒ **索引件必须与入口同规格上棘轮**；历史/失效条目一律进 archive（深度≥2 目录天然豁免 INDEX 登记），别再塞回索引件 |

## 11. 复用清单

1. 确认 `AGENTS.md` 已是**唯一事实源**且**自包含**（R1/R2）；不是则先把散落规则收拢进来。
2. 建/修别名件（`CLAUDE.md`、`.cursorrules`）：**只写一行指针**＋极少不可让步口径（R4）。
3. **清点工具本地层**（`grep -rn '\.workbuddy/'` 等）：把里面的**规则与经验坑迁入 git**，会话流水留在原地（R6/D3）。
4. 修所有「必读清单 / 开场白模板」里指向工具本地路径的条目，改指新家（R7）。
5. 在入口文件写「会话口令」段（开工/收尾/记一下），定义处唯一（R10）。
6. 给 lint 加六条断言：入口字节棘轮 / 禁指工具本地路径 / 必需锚点小节齐全 / 别名只含指针 / 热点文档体量 / 索引件体量；各做一次变异自证（R7/R8/R9）。
7. **清掉任何第二规则目录**，并写进入口禁令（R3）。
8. 新工具接入时只做一件事：查它是否读 `AGENTS.md`；不读就加一枚指针别名（E1）。
9. 别再加第 4 个「必读大件」——待排期/预研类知识用**轻量索引件**（排期池一行）承接，不当必读、不占行数预算；但索引件**本身也要上体积棘轮**（它没有行数预算兜底，历史流水一迁入就爆——本项目实测排期池 93.7% 是被迁入的历史流水表）。
10. 棘轮下要加新内容，走**净零字节扩容法**：先在同段删掉等价冗余（如「相关目录已 gitignore，见忽略清单」这类可自行推导的复述），腾出字节再加新指针；改完立刻跑闸确认未越顶——否则「只许减不许增」会被逼成「放宽阈值」，棘轮反被架空。
11. 换机动作脚本化：把「干净机器 clone 后逐条目检」写成 `tools/bootstrap_check.sh`，一条命令报出「入仓件里指向工具本地层的活指针」＋「需重设的版本钉/工具链」。

# Agent 协作项目的上下文治理：三层按需加载 + 工单生命周期 + 漂移守护（可复用）

| 项 | 值 |
|---|---|
| 标签 | `engineering` `AI协作` `文档治理` `守护脚本` `多会话并行` |
| 成熟度 | ✅ 已落地并验证（LifeHarness 治理二轮，2026-10-02，10 提交收口 + 守护变异校验） |
| 来源项目 | LifeHarness（Flutter 个人管理 App）· `AGENTS.md` / `docs/STATUS.md` / `docs/INDEX.md` / `tools/doclint.py` / `tools/run_gate.sh` |
| 参考实现 | `tools/doclint.py`（死链 + 漂移五检，约 90 行 Python）；`docs/superpowers/{specs,plans}/2026-10-02-context-governance*`（设计与实施计划） |
| 适配成本 | 低～中。纯文本 + Python + bash，无语言绑定；主要改动点是把守护五检的文件名单与行数预算改成自己项目的值，并接进自家门禁脚本 |

> 解决「AI 会话越长文档越肥、新会话开场必读爆量、过期信息与现行规格混在一堆」的腐化问题。
> 适用：由 AI 代理多会话接力开发、文档同时给人和机器读的项目（含单人项目）。
> 不适用：纯一次性脚本项目；文档由非 AI 工具链自动生成且无法加门禁的项目（R7 落不了地，其余仍可用）。

---

## 0. 一句话定义

把「会话开场必读」压缩成**入口规则文件 → 状态源 → 文档地图**三层（合计 ≤150～200 行），给每份文档一个**由机器守卫的登记条目与生命周期**，让过期内容只能进归档、不能再污染现行文档。

## 1. 术语

| 术语 | 说明 |
|---|---|
| 三件套 | `AGENTS.md`（禁令/环境/门禁，多数 AI 工具自动注入）+ `STATUS.md`（唯一状态源）+ `INDEX.md`（文档地图） |
| 活文档 / 归档 | 活＝现行依据，被守护扫描；归档（`docs/archive/`）＝闭环卷宗，只进不出、互引不重写、扫描豁免 |
| 工单 | 一次批次的交接规格：交棒话术 / 验收清单 / 拍板记录 / 开场白等一次性文档，生在新建区、死进归档 |
| doclint | 文档门禁脚本：死链体检 + 漂移守护五检，红灯 exit 1 |
| 体积守恒 | 拆分/搬家类改写用「核心字符数」做迁移前后对账，防静默丢内容 |

## 2. 需求规则（编号即验收项）

- **R1 三层开场**：新会话只按 入口文件 → `STATUS.md` → `INDEX.md` 顺序读，INDEX 命中行才展开具体文档；三层各设行数预算（示例 90/60/130），超预算即守护红灯。
- **R2 唯一状态源**：HEAD/发版号/DB 版本/门禁基线/下一站/并行互斥面**只写在 STATUS**；历史时点沉变更日志文末；其它文档出现状态数字算违规（不钉易漂移的 sha，写「看 git log」）。
- **R3 地图登记制**：docs 顶层与工单区的每份跟踪文档，文件名必须出现在 INDEX（含「类型｜活/闭环｜何时读」），漏登记守护红灯——INDEX 的更新由机器倒逼，不靠自觉。
- **R4 工单生命周期**：新工单只准建在 `docs/handoff/`；批次收口即 `git mv` 入 `docs/archive/` 并更新 INDEX 一行；归档后不再改写内部互引（历史坐标允许失效，扫描豁免）。
- **R5 历史与现行分离**：逐版修订记录、变更日志、一次性盘点/审计不进主文件正文——整体迁 archive 成独立《修订史》类文件，主文件只留一行指针；**三源冲突优先序要指向迁出的实体文件**（例：修订史 > 原型 > 计划文档）。
- **R6 产物不入库**：截图/取证/browser profile/一次性补丁坟场一律 gitignore，留底放仓库外目录；验收文档只写结论不挂图。
- **R7 机器守护 + 硬触发点**：doclint 五检（①工单落位 ②INDEX 覆盖率 ③「历史节复活」判定（如需求清单再现 `## 十、` 或 >1000 字符长行）④主文档长行上限 ⑤三件套行数预算），红灯 exit 1；并**接在全量门禁/CI 脚本的最前面**（红灯不起测试），保证收口时刻必被跑到。
- **R8 守护自证**：每条守护合入前做变异校验——注入违规样本必须红、还原必须绿；没被红过的守护等于没有。
- **R9 跨工具入口别名**：`CLAUDE.md`、`.cursorrules` 等各家自动读取的入口文件只写一行「唯一事实源是 AGENTS.md」+ 三条不可让步口径；换 agent 工具不丢规则（Qoder/Claude Code/Cursor 实测各自自动拾取）。
- **R10 并行会话互斥面进 STATUS**：哪些文件属于别的会话（只读禁写）当期列明；批内提交一律**文件级 pathspec**（见坑 K1）。
- **R12 协作动词口令化**：入口文件定义「**开工 / 收尾 / 收尾并推送 / 记一下 <主题>**」四个魔法词并写清各自动作序列（开工＝读入口→STATUS→下一站活工单直接干；收尾＝六步仪式）。日常批**禁止再写长开场白**——开场超过两个词，就说明上一轮 STATUS 下一站行没写全，该补的是收尾而不是开场。
- **R13 人机双入口对齐**：面向人的 `README.md` 与面向 agent 的入口三件套同构（导览列同一张地图），且 README 纳入 doclint 扫描面；本项目实测 README 曾教人裸跑全量测试、模块清单过期——人侧入口同样会腐，只是没人查。
- **R11 大改全脚本化**：快照（gitignored `tmp/`）→ 命中断言 → 体积守恒对账 → 失败自动回滚；批量修改写成脚本文件执行，不用 heredoc。

## 3. 状态机 / 数据模型

文档生命周期：`现行(docs 顶层/模块计划) → 活工单(docs/handoff/) → 闭环归档(docs/archive/)`，只进不出。
INDEX 行＝登记表：`路径 | 类型 | 状态 | 何时读`；守护用「文件名子串 ∈ INDEX 文本」判覆盖率。
不变式：任一时刻 STATUS 只有一份、修订史只增不回灌主清单、跟踪文件中不含截图类产物。

## 4. 关键算法或流程

拆分搬家（R5）的判定流程：① 锚点探测（grep 节标题拿行号，勿心算）→ ② 逐字切出 → ③ 新文件 = 固定头（原样字符串常量，参与对账时常量与写入**同源复用**）+ 迁出内容 → ④ 主文件原位换成一行指针 → ⑤ 对账：`核心字符(迁出)+核心(留) ≥ 核心(原文) − 容差`，核心字符＝剔除 `[*|>#`（）「」：；。、` 与空白后的计数 → ⑥ 任一断言失败整体回滚快照。
doclint 豁免设计（都有根因，见 §10）：行级豁免词（已删除/找回/git log…）、`*` 通配引用跳过、文件级豁免表带**理由注释**、路径正则要求前置边界字符且扩展名**长名优先**（json 在 js 前）。

## 5. 与数据层的边界规则

- **D1** 治理只动文档与工具脚本，**零代码/测试改动**，全量测试基线不因治理轮重跑。
- **D2** 代码里对文档路径的引用若是**注释/文档字符串**，搬迁时同步改写；若存在真实读取（`File('docs/…')`），搬迁前必须先跑引用扫描并把该文档列入「原地不动清单」。

## 6. 性能规则

- **P1** doclint 目标秒级：只扫跟踪 md（archive/预研/superpowers 豁免），一次 `git ls-files` + 逐行正则即可。
- **P2** 治理收益的量化口径：开场必读行数（本例 ≈2700 → 133 行）、docs 盘体积（59MB → 30MB）、INDEX 覆盖数（守护首跑抓出 7 份漏登记）。

## 7. 扩展点

- **E1** 原型/大文件行数预算检（本次未做，INDEX 已标注候选）。
- **E2** 归档到期清理：archive 中超过 N 版未引用者可 `git rm`（历史仍可考古）。
- **E3** 把 doclint 挂 pre-commit——注意 **hooks 不随仓库传播**，换机器会丢，优先 R7 的「门禁脚本前置」做法。

## 8. 实现骨架

```
仓库根/
├── AGENTS.md          # ≤90 行：禁令/环境/门禁/工单生命周期 + 指向 STATUS、INDEX
├── CLAUDE.md          # 1 行别名 → AGENTS.md（其它工具同理 .cursorrules）
└── docs/
    ├── STATUS.md      # ≤60 行：HEAD|发版|DB|门禁基线|下一站|互斥面（状态只改这里）
    ├── INDEX.md       # 文档地图：路径|类型|活/闭环|何时读
    ├── handoff/       # 活工单（新工单唯一出生地）
    ├── archive/       # 闭环归档 + 修订史 + 瘦身前存档（只进不出）
    └── 需求清单.md     # 只含现行定义，修订记录在 archive/需求修订史-*.md

# tools/doclint.py（exit 1 即红灯）
死链: git ls-files 的现行 md → 正则抓 docs|prototype|tools 路径 → os.path.exists
守护: ①^(工单前缀) 落 docs 顶层 → 红   ②顶层/handoff 文件名 ∉ INDEX → 红
     ③需求清单 ^## 十 / len(行)>1000 → 红   ④交接 len(行)>800 → 红
     ⑤三件套行数 > 预算 → 红
豁免: 行含「已删除/找回/git log」 · 引用含 * · FILE_EXEMPT{路径:理由}

# tools/run_gate.sh 顶部接线（收口/发版机械触发点）
"$PY" tools/doclint.py || { echo "DOCLINT-RED"; exit 1; }   # 红灯不起测试
```

## 9. 验收用例清单

- [ ] 新会话只读三件套能答出：当前状态在哪看／下一站是什么／哪些文件禁动（三问三答）。
- [ ] 变异校验：在 docs 顶层放一份「交棒话术-test.md」→ doclint 红；删掉 → 绿。四条守护各来一遍。
- [ ] `git ls-files | grep -c 'acceptance\|shots/'` = 0；`.gitignore` 含截图/快照目录规则。
- [ ] 拆分对账脚本输出「核心字符 迁出=原文」零误差；主文件行数落在目标区间断言内。
- [ ] 现行文档集死链扫描 0 红；INDEX 覆盖率检查 0 红。
- [ ] 归档工单 `git log --follow` 可追、INDEX §归档行可达。
- [ ] 并行会话的未提交 M 文件在治理全程后仍保持 M（未被卷进任何治理提交）。

## 10. 已知坑

| 现象 | 根因 |
|---|---|
| 「局部提交」把并行会话的未提交改动一起提交了 | `git commit -- docs` 目录级 pathspec 读的是**工作区内容**，不是我的暂存。正解：`git status/diff --name-only` 取自己改过的**文件级清单**（rename 要含新旧双路径），`--pathspec-from-file=<NUL 分隔清单> --pathspec-file-nul` 提交；误卷后本地未推送时 `git reset HEAD~1` + 精确清单重放 |
| 计划删的「陈旧」浏览器 profile 差点删掉热数据 | 目录 mtime 全在当天——多轮治理前的判据要先对**当前实况**复核（并行会话正在用）。凡「按体积立项的清理」先查活跃度再查体积 |
| `.json` 引用被报成 `.js` 死链；`#### V1.x` 被 `### V1.` 子串误伤；`features/tools/widgets/x.dart` 被当成 `tools/` 引用 | 正则扩展名交替**顺序**（长名在前）+ 缺**前置边界** `(?<![A-Za-z0-9_/.-])`；断言关键词也要防标题层级子串 |
| 守护一片绿其实是假绿 | 行豁免词写成 `"*" in line`，Markdown 粗体行全被跳过。通配符只能豁免**引用本身含 \* 的行**，不能按 line 判 |
| 批量 patch 一个文件断言失败，后面文件全没改 | 多文件逐字节 replace 不原子；fail-fast 后要从头重放整批。锚点必须用文件里的**真实字符串**（`-v3.html` 这类文中简写不是可命中锚点） |
| 控制台里文件名全是乱码，照着乱码修名字连错两次 | Windows 终端 GBK 显示 UTF-8 所致。读中文文件名一律 `git -c core.quotepath=off` 或 python `repr()` 输出，勿信 shell 打印 |
| 拆分后内容疑似丢失却全绿 | 对账用的「固定头常量」与真正写入的字符串不同源，减法误差几十字符被容差吞掉。同源复用变量 + 断言打印双方计数 |
| 脚本插 INDEX 行把下一行表头行首吞了 | Markdown 表格行做锚点的经典坑：插完必须跑列数校验（5 列 → `split('|')` 段数 7） |
| 交接文档越写越长，头部三条「当前状态」单行 4150 字符 | 会话按旧惯性把「历史时点」追加进头部引用块。解法不是删字，是 R2/R5 把状态和历史各归各位，再用守护④挡长行 |

## 11. 复用清单

1. 建三件套 + `docs/{handoff,archive}/` 目录，入口文件写明「开工先读三件套」。
2. 抄 §8 的 doclint 五检（改文件名/预算/前缀为你项目的值），本地变异校验四检后入库。
3. 把 doclint 接到你最常跑的收口脚本/CI 第一条命令。
4. 把逐版「修订记录/变更日志」整段搬家成独立史文件 + 一行指针（用体积守恒脚本搬，别手删）。
5. 截图/取证产物加 gitignore + 仓库外留底目录，历史跟踪者 git rm。
6. 新会话互斥面/下一站写进 STATUS 一次性交代；后续只改这一处。
7. 若同时用多种 AI 工具：CLAUDE.md / .cursorrules 一行别名进仓库。
8. 在入口文件写「会话口令」段（R12），并把 README 与三件套一起纳入 lint 扫描（R13）。

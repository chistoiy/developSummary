# Agent 会话运作仪式：开工/收尾口令 + 两档门禁 + 20 分钟窗口 + token 预算（可复用）

| 项 | 值 |
|---|---|
| 标签 | `engineering` `AI协作` `流程` `成本预算` `门禁` |
| 成熟度 | ✅ 已落地并验证（LifeHarness 2026-10-06 拍板成文；口令/收尾六步/守护六·七/打点闸全部机器强制，真实批 18m44s 窗内达标与超窗归因三选均有实测案例） |
| 来源项目 | LifeHarness（Flutter 个人管理 App）· `AGENTS.md`（会话口令/收尾仪式/验证门禁/禁令段）+ `docs/开发计划书.md` §7.2/§7.4/§7.5 |
| 参考实现 | `tools/timelog.sh`（五段打点＋窗内净耗判定）、`tools/status_set.py`（STATUS 轮转＋体积硬闸 `--check`）、`tools/doclint.py` 守护六（活施工工单缺「⚙ 执行面板」红灯）与守护七（STATUS 单行/全文/字段体积）、`tools/ftest.sh`（测试单轨批跑） |
| 适配成本 | 低～中。全部是文本规则 + bash/python 工装，无语言绑定；主要改动点是把自己的门禁命令清单、五段预算数值与体积上限换成自己项目的值 |

> 解决「AI 多会话接力开发时，每轮开工要人复述背景、收尾全靠自觉、提速只能砍验证、token 与墙钟成本两头失控」的运作问题。
> 适用：由 AI 代理多会话接力、每批工作有明确「开工→实现→门禁→文档→提交推送」流水的项目（含单人项目）。
> 不适用：无人机接力的一次性任务；没有可机判验收手段的纯探索性研究（R7/R11 落不了地，其余口令/预算口径仍可用）。

---

## 0. 一句话定义

把一次 AI 工作批的**开始与结束各固定成一个口令**（开工/收尾），把**规格前置编译进工单执行面板**（开工会话只执行不决策），把**验证拆成两档**（批内增量／收口全量），再用**打点闸＋体积闸＋调用预算**把墙钟与 token 变成可度量、可归因、可改进的指标——提速重心从「减验证」移到「并行化＋预编译＋模板化」。

## 1. 术语

| 术语 | 说明 |
|---|---|
| 会话口令 | 入口文件里定义的最小动词表：开工 / 收尾 / 收尾并推送 / 记一下 \<主题\>；用户只发口令，动作序列全由文件驱动 |
| 执行面板 | 施工类工单开头的六项可执行规格（见 R3），开工会话的唯一规格依据 |
| 两档门禁 | 档一＝批内增量（只跑面板点名文件）；档二＝收口/发版全量（独占、攒批、每轮只跑一遍） |
| 窗口 | 方案已定的一个批，从开工到双端推送回执的墙钟预算（示例 20 分钟）；等用户确认与重型攒批动作算窗外 |
| 三件套 | `AGENTS.md` + `STATUS.md` + `INDEX.md`（文档状态面见姊妹篇《上下文治理》，本文管的是**会话运作面**） |
| 互斥面 | STATUS 当期行列明的「属于其他并行会话、只读禁写」文件清单 |
| 归因三选 | 超窗时刻在变更日志行尾三选一：工单欠预编译／门禁超时／网络回退，并指到具体段 |

## 2. 需求规则（编号即验收项）

- **R1 口令表进入口文件**：只给用户极少几个动词（开工／收尾／收尾并推送／记一下），每个词写清展开后的动作序列；限定范围用「开工 \<工单名\>」。用户不需要记任何流程细节，其余全由入口文件驱动。
- **R2 开工＝三层读＋面板读**：新会话按 入口文件（自动注入）→ STATUS 下一站行 → 活工单执行面板 的顺序读，**其余不读**——不通读工单正文、不做全仓检索。复杂交接才用开场白模板；日常批**禁止再写长开场白**——判定句：开场超过两个词，就说明上一轮收尾没把 STATUS 下一站行写全，该补的是收尾而不是开场。
- **R3 工单预编译＝执行面板（开工窗口内只执行不决策）**：新立施工类工单必须带六项面板——①受影响测试文件精确清单（列齐一次，防「漏了补一轮」）②变异刀清单（锚点＋预期红用例名）③新增常驻用例文件名 ④文档回灌三处的目标行与**预写成句** ⑤下一复测包编号与代码面归属 ⑥互斥面。缺面板＝doclint 红灯（存量进白名单、只许减）；面板缺项不阻塞开工，但超窗自动归因「工单欠预编译」，欠账记回**立案会话**而非开工会话。
- **R4 收尾六步仪式（口令「收尾」即执行，顺序固定）**：①门禁：受影响测试 + 文档改动随跑 doclint 清零 + `timelog report` 贴判定行；②状态：只更新 STATUS（HEAD/发版/DB/门禁数/下一站/互斥面）；③工单流转：已闭环批次 `git mv` 入 archive 并更新 INDEX 一行；④登记：变更日志追加 ≤3 行（结论+提交+发版），细节留工单；⑤提交：文件级 pathspec 局部提交，推送/发版**另行取得同意**；⑥可复用方案按需沉淀。状态变化只改 STATUS 一处，历史时点只沉变更日志。
- **R5 「记一下」＝直落指定处**：用户说「记一下 \<主题\>」，结论必须落进 STATUS/INDEX/变更日志的对应格，**不许只回「收到」**——口头应答不落盘等于没记。
- **R6 两档门禁，全量每轮只跑一遍**：批内增量只跑面板清单（经单轨测试工装，治并发崩溃）；收口/发版才跑全量，且全量是独占资源（示例约 12 分钟），**窗口内一次批跑、并发会话不同场抢 CPU/IO**。跑完以 `rc`＋尾行定案即算门禁过；**对日志读数起疑时先做便宜判定**（要数覆盖面用 `--reporter json`，秒级），**任何重跑（尤其独占全量）必须先取得同意**（见坑 K1）。
- **R7 时间窗＋五段预算，机器可度量**：方案已定的批从开工到推送回执 ≤20 分钟墙钟（示例值），五段：P0 开工 0–2'（只读三层+面板）→ P1 实现 2–10'（静态分析须在测试起爆前收口）→ P2 门禁 10–14'（测试后台跑的**同时**主线起草文档）→ P3 文档 14–17'（按面板预写成句落三处+秒级 doclint）→ P4 提交推送 17–20'（双端**并行起推**）。打点规则：`start` 是开工第一条命令（漏了五段分解直接拿不到，可用 `--from` 回填）；**提问前先 `mark 窗外·等确认`、答复后立刻续段**——等确认与构建/上传/装机都算窗外不计窗内判定。超时＝变更日志行尾归因三选＋指到具体段；**同一流水线连续两批超时＝流程事故**，回工单补口径而不是继续赶路。
- **R8 并发纪律只许一种形态**：重型测试进程全程单轨、窗口内一次批跑；与后台测试同场只许轻量工装（node 脚本/git/lint/文档起草）；变异刀逐刀串行，复原一律整文件快照回写＋md5 断言（禁止拿变异串反解，见坑 K4）。
- **R9 并行会话互斥面进 STATUS**：当期列明哪些文件属于别的会话（只读不写不提交不回退）；提交一律**文件级** pathspec（目录级会卷走他人工作区改动，手法见《上下文治理》坑 K1）。
- **R10 读取成本＝token 预算，按三条硬口径执行**：①超长行/大文件**禁止整读**——三件套收尾按锚点 grep 取要改那段，STATUS 类热点文件用轮转工具 `--get <字段>` 取段；②一轮收尾的模型调用预算给死（示例 12–20 次：静态分析 1／增量测试 1–2／改文档 3–5／提交 1／双端推送 2–3／报告 1），**超预算即自造浪费**；③同一文件的多次取读合并成 ≤3 条命令（一条命令多个 `sed -n 'a,bp'`／多锚点 `grep -n 'x\|y\|z'`）——实测十几条一行命令白花约 4 分钟。配套体积硬闸：STATUS 只许「本批／上一批」两级叙事（第三级即红灯），单行/全文/字段正文三维体积上限由 `--check` 守护（行数预算挡不住单行几万字符，见坑 K5）；超限走 `--force` 并在工单写理由。
- **R11 规则制定纪律＝立规矩必带三件套**：每条规则写「规则本体 + 为什么 + 判定标准」；**凡可机判的规则必须做成红灯闸、接在必跑位置（门禁脚本最前）、并变异自证**——没被红过的守护等于没有（手法见《变异自证工装》《棘轮守护》）。人读的纪律（如「推送需先同意」）留在入口文件禁令段并靠收尾步骤兜底。给人看的回执分档 L0/L1/L2（目标唯一直接干／跨屏摘要不阻塞／不可逆或多义停下确认），**回执禁止出现 id/行号/类名/函数名**，连带影响说功能语言（「这两屏会一起变」）。
- **R12 派发边界（子代理≠默认提速）**：派发只在三条件同时成立时为正收益——大批量、文件集严格互斥、主线程同窗另有非代码要务。小批单任务派发是净负收益（实测：派发做一屏＝78 分钟且主线程全程等待；改内联直写四屏 1818 行＝42 分钟；同日三次派发被中断每次约 10 分钟纯损耗）。实现批默认主线程内联，派发只留给「独立审计/批量走查/工装脚本」这类真能并行的活。
- **R13 提速不砍验证**：任何瘦身只动**重复执行与读取成本**（变异只钉本批新增守护、单批封顶 3 刀；相邻回归三件套退出每批随收口轮跑；清单外用例不补跑）；**不削减项＝机器闸（静态分析+面板点名增量+变异+文档 lint+产物预检）、真机门、确认门**。

## 3. 状态机 / 数据模型

批次生命周期：`工单立案（带面板）→ 开工 P0 → 实现 P1 → 门禁 P2 → 文档 P3 → 提交推送 P4 → 收尾六步 → 工单归档`。
STATUS 叙事只有两级：`本批（待填→填写）→ 上一批（自动降级）→ archive 沉档`；第三级出现即红灯。
打点账本不变式：`窗内净耗 = 总墙钟 − 「窗外·」前缀段 − 等确认段`；判定行只有「达标/超（附归因）」两种取值。

## 4. 关键算法或流程

超窗归因链：report 判「超」→ 看五段哪段吃预算 → 归因三选写进行尾（工单欠预编译＝P0/P1 段读了不该读的或现场决策；门禁超时＝P2 段清单没列全或全量被并发污染；网络回退＝P4 段链路重试）→ 行尾补一句具体动作（如「P1 大文件分批取读」），否则下一批无从改进。
文档段模板化：面板第④项把 STATUS/INDEX/变更日志三处的**目标行与整句预先写好**，P3 段从「组织语言」退化成「粘贴+核对」，这是 P3 压到 3 分钟的前提。
并行推送：双端（如 Gitee/GitHub）并行起推而非串行，链路回退时间单独计账；推后必回读远端 HEAD 比对（见坑 K7）。

## 5. 与数据层的边界规则

- **D1** 运作仪式只动流程与工装，不豁免任何验证门（R13）；「瘦身三条」瘦的是覆盖面重复，不瘦覆盖本身。
- **D2** 热点状态文件（STATUS 类）的修改必须走轮转/取段工具（`--rotate`/`--set 字段 --text-file`／`--get`），**勿手改超长行、勿 heredoc**——正文走临时文件。
- **D3** 门禁清单外若静态分析红或红灯直关可补跑，其余一律攒到收口轮；攒批动作（全量/出包/装机）不进窗口。

## 6. 性能规则

- **P1** 秒级件随手跑（doclint/lint/便宜判定），分钟级以上才攒批；判定成本差是「先做便宜判定」口径的依据。
- **P2** 报耗时前先确认样本没被并发污染（别的会话在跑重任务时的 elapsed 不可作基线，可拉数倍）。
- **P3** 收益量化用两个数：开场必读行数/字节数（读取成本）与窗内净耗分钟数（墙钟成本），都由守护与打点闸自动产出，不靠体感。

## 7. 扩展点

- **E1** 面板六项可按项目增删（如出包项目加「预检命令与期望 versionCode」项），但「开工只执行不决策」的原则不变。
- **E2** 调用预算可细化到按段计账（每段 mark 附带读取次数探针），用于定位预算超支来源。
- **E3** 口令表可扩展「复验」「走查」等真机类口令，动作序列同样写进入口文件。

## 8. 实现骨架

```
# 入口文件（AGENTS.md 类）关键段
## 会话口令（用户只需这几个词，其余全由本文件驱动）
- 「开工」   = 读本文件 → STATUS → 下一站行指向的活工单【执行面板】，按批次顺序开工；
              带面板的批只读面板与批次规格，不通读工单。限定范围写「开工 <工单名>」。
- 「收尾」   = 六步仪式：门禁(report 贴判定行) → 只改 STATUS → 工单 git mv 归档+INDEX 一行
              → 变更日志 ≤3 行 → 文件级 pathspec 局部提交 → 按需沉淀。
- 「收尾并推送」= 收尾 + 双端 push（并行起推；推后回读远端 HEAD 比对）。
- 「记一下 <主题>」= 落进 STATUS/INDEX/变更日志对应处，不许只回「收到」。

## 验证门禁（两档）＋ 收尾轮成本口径
- 批内增量只跑面板清单；收口/发版才全量（独占、每轮只跑一遍、rc+尾行定案、重跑须同意）。
- 收尾三件套按锚点 grep 取段不整读；一轮预算 12–20 次调用，超预算＝自造浪费。

# tools/timelog.sh —— 窗内净耗判定
timelog.sh start <slug> [--from 'YYYY-MM-DD HH:MM:SS']   # 开工第一条命令
timelog.sh mark <段名>          # 段名以「窗外·」开头者不计窗内
timelog.sh report               # 分段 + 窗内净耗 + ≤20' 判定行（贴进收尾报告）

# 工单面板（活施工工单开头）—— 缺则 doclint 守护六红
## ⚙ 执行面板
1 受影响测试: test/a_test test/b_test        2 变异刀(≤3): <锚点→预期红用例>
3 新增常驻用例: test/c_test                  4 文档回灌: STATUS 下一站=〈预写成句〉/ INDEX 行 / 变更日志行
5 下一复测包编号: NNNN                        6 互斥面: 只读 tools/x.js（并行会话在飞）

# STATUS 轮转 + 体积闸（守护七）
status_set.py --rotate                       # 本批正文→上一批，本批置待填
status_set.py --set 本批 --text-file tmp/x.txt
status_set.py --get 下一站                    # 取段代替整读
status_set.py --check                        # 单行≤1200字符·全文≤16KB·字段≤400·两级不复活
```

## 9. 验收用例清单

- [ ] 新会话只发「开工」两个字，零背景复述即可按活工单面板推进到可评审产物。
- [ ] 真实施工批 `timelog report` 出「窗内净耗 ≤20 分钟」判定行；有超窗批次时，变更日志行尾存在归因三选＋具体段名。
- [ ] 变异校验守护六：删掉活施工工单的执行面板小节 → doclint 红；还原 → 绿（存量白名单外新工单必测）。
- [ ] 变异校验守护七：往 STATUS 塞一条超长行/加第三级叙事字段 → `--check` 红；`--rotate` 后 → 绿。
- [ ] 收尾六步走完后再无人肉追问「现在什么状态/下一步是什么」（STATUS 下一站行自答）。
- [ ] 抽查一轮收尾的模型调用次数落在预算区间；出现整读超长文件/逐行取读大文件的轮次能指认超支段。
- [ ] 并行会话互斥面生效：其他线的未跟踪/在飞文件未被本会话提交或回退。

## 10. 已知坑

| 现象 | 根因 |
|---|---|
| 全量测试日志里路径数远小于预期，误判「没跑全」又烧一遍独占全量 | 并发 reporter 落盘时只写部分文件路径——**日志出现的路径数≠覆盖面证据**（同一命令两遍同为 2111，路径数分别 82/118）。以 rc＋尾行定案；起疑先跑秒级 `--reporter json` 便宜判定 |
| 26m44s 判「超窗」，实际施工段达标 | 等用户拍板的 8 分钟没剔出窗口。提问前必须先 `mark 窗外·等确认`，答复后立即续段；构建/上传/装机同理加「窗外·」前缀 |
| report 出 `0m00s`，五段分解直接拿不到 | `timelog start` 没当开工第一条命令，只能拿文件 mtime 补账。补救通道是 `--from` 回填首动作时刻；根因是把打点排在读面板之后 |
| 变异复原把 40 万字原型撑成 16MB 废文件 | 用 `src.split(变异串).join(原文)` 反解：变异串恰为空串时 `split('')` 逐字符拆开再插回。复原必须写回**变异前内存里的原文快照**＋md5 断言 |
| STATUS 行数预算 ≤60 一切正常，文件却滚到 94KB、表头单行 7,960 字符 | 行数预算对「超长行」失明。体积闸必须按单行长度/全文体积/字段体积三维做，配轮转工具把叙事钉死两级 |
| 派发单任务做一屏 78 分钟，比内联直写四屏还慢一倍 | 派发收益三条件不成立（批量小、文件不互斥、主线程无可并行的第二要务），主线程全程干等；被中断的派发每次约 10 分钟纯损耗 |
| 规则写了十几条，会话照样「只回收到不落盘」「开场写长开场白」 | 口头规则无执行机制。可机判的必须落闸（面板守护/归因行/预算判定行）；不可机判的进入口文件禁令段并让收尾步骤成为兜底触发点 |
| 双端推送「成功」后远端 HEAD 对不上 | 链式命令 `A && B & C &` 的分组陷阱把前置命令圈进第一个后台任务，两端并行起推变成抢跑；推后必 `ls-remote` 回读比对 |
| 断言按观感写死计数/字符串，自造假红多烧一轮闸 | 面板预写成句与闸期望值都必须**现算**（页面内探针/脚本量测），别把「看起来对」当常量 |
| 报「全量太慢，砍掉」后回归裸奔 | 把提速理解成减验证。正确对象是重复执行与读取成本（R13 不削减项清单）；慢的真实来源常是并发污染（P2）与逐行取读（R10③） |

## 11. 复用清单

1. 新项目开局**整段抄 §12 种子**：落 `AGENTS.md` + 三条随附件（CLAUDE.md 别名 / STATUS 头字段 / 工单面板六项），填占位、按自家门禁裁到行数预算；已有项目按本节逐条改造。
2. 给施工类工单立「执行面板」模板（受影响测试清单/变异刀清单/新增用例/文档回灌预写成句/攒批编号/互斥面），并在文档 lint 里加「活工单缺面板」红灯 + 存量白名单。
3. 抄 §8 的 `timelog` 五段打点：起表＝开工第一条命令；等确认与重型攒批动作加「窗外·」前缀；收尾必贴判定行；超时归因写进变更日志行尾。
4. 门禁改两档：批内只跑面板清单，全量攒到收口/发版且每轮只一遍；把「重跑先同意 + 先做便宜判定」写成硬口径。
5. 给热点状态文件装轮转/取段工具与三维体积闸（单行/全文/字段），把「禁止整读超长文件、一轮调用预算 12–20 次」写进入口文件的成本口径段。
6. 规则登记时逐条标「硬闸/自觉」；凡选硬闸的，当天完成红灯接线＋变异自证，没被红过的守护视为不存在。
7. 定派发判据三条件并写进流程文档；不满足时实现批走主线程内联。
8. 双端/多端推送改并行起推＋推后回读比对；推送授权本身留在收尾第⑤步之外单独取得。

## 12. 项目开局初始化模板（AGENTS.md 种子 · 整段抄走即用）

`<…>` 为占位符；「⚙」标注处＝可机判规则，按 R11 须做红灯＋变异自证后才算落地，一时做不出工装的保留规则本文并显式标「自觉」，别留死闸。抄完的入口文件应裁到自家三件套行数预算内（本模板约 70 行）。

````markdown
# <项目名> — Agent 指南

<一行项目定位（技术栈/目标平台）>。本文件只放「每个会话都需要」的事实与禁令。

## 开工先读（三层按需，勿全仓检索）
1. `docs/STATUS.md`（≤60 行）——HEAD／发版／门禁基线／下一站工单／互斥面，唯一状态源。
2. `docs/INDEX.md`——文档地图；按任务类型找到需要的那几行，只读那几行指向的文件，不通读 docs/。
3. 下一站行指向的活工单（`docs/handoff/`）——批次规格唯一依据；带「⚙ 执行面板」的批只读面板与批次规格。
- 三源冲突优先序：<需求修订史> > <UI/设计事实源（原型等）> > <计划文档>；拿不准先问，不自己定。

## 工单生命周期
- 新工单直接建在 `docs/handoff/`；批次收口即 `git mv` 入 `docs/archive/` 并在 INDEX 更新一行；归档只进不出、互引不重写。
- ⚙ 施工类活工单必须带「⚙ 执行面板」六项（见文末模板），缺＝文档门禁红灯；存量白名单只许减。

## 验证门禁（两档）
- 批内增量：只跑面板点名的受影响测试（<增量命令>）；收口/发版才跑全量（<全量命令>，约 <耗时>，独占资源勿并发抢跑）。
- ⚙ 同一收口轮全量只跑一遍：rc＋尾行定案即过；对读数起疑先做秒级便宜判定（如 `--reporter json`），任何重跑必须先取得同意。
- ⚙ 文档域改动随跑 <doclint/lint 命令>，红灯清零；秒级件随手跑，分钟级以上才攒批。

## 单批时间窗（五段打点）
<打点脚本> start <slug>（开工第一条命令，可 --from 回填）→ mark <段名> → report 贴判定行。
五段预算：P0 开工读面板 ≤2'／P1 实现（静态分析在测试起爆前收口）／P2 门禁（测试后台跑的同时主线起草文档）／P3 文档三处按面板预写成句落／P4 提交＋多端并行推送。
等用户确认与构建/上传/装机＝段名加「窗外·」前缀，不计窗内；超窗 ⇒ 变更登记行尾归因三选（工单欠预编译／门禁超时／网络回退）＋具体段名；连续两批超＝流程事故，回流程文档补口径。

## 收尾轮成本口径（token）
- 超长行/大文件按锚点 grep 取段，禁整读；<热点状态文件> 用轮转/取段工具（--rotate / --get 字段 / --set 走临时文件），⚙ 体积硬闸＝单行 ≤<1200> 字符·全文 ≤<16KB>·字段正文 ≤<400> 字符·叙事只许本批/上一批两级。
- 一轮收尾模型调用预算 <12–20> 次（静态分析 1／增量测试 1–2／改文档 3–5／提交 1／推送 2–3／报告 1），超预算即自造浪费。
- 同一文件多次取读合并成 ≤3 条命令；派发子代理只在三条件同时成立时做（大批量·文件集互斥·主线程另有非代码要务），否则主线程内联直写。

## 会话口令（用户只需这几个词，其余全由本文件驱动）
- 「开工」＝读本文件 → STATUS → 下一站活工单面板，按批次顺序开工；限定范围写「开工 <工单名>」。日常批禁止长开场白——开场超两个词＝上一轮 STATUS 下一站行没写全，先补收尾。
- 「收尾」＝六步：门禁（增量+lint+打点 report 贴判定行，红灯清零）→ 只更新 STATUS → 已闭环工单归档+INDEX → 变更登记 ≤3 行 → 文件级 pathspec 局部提交 → 可复用方案按方案库模板沉淀（点名时）。
- 「收尾并推送」＝收尾＋双端 push（并行起推；⚙ 推后 ls-remote 回读远端 HEAD 比对）。
- 「记一下 <主题>」＝结论落进 STATUS/INDEX/变更登记对应处，不许只回「收到」。

## 规则制定纪律
- 每条规则＝本体＋为什么＋判定标准；可机判的必须成红灯闸、接在必跑位置（门禁脚本最前）、变异自证——没被红过的守护等于没有；不可机判的显式标「自觉」。
- 给人看的回执分档：目标唯一直接干／跨视图仅摘要／不可逆或多义停下确认；回执禁止出现 id/行号/类名/函数名，连带影响说功能语言。

## 环境事实（本机）
<工具链绝对路径／镜像与网络回退／凭据入口等会话必需事实，≤6 行>

## 禁令（违反会被驳回）
- <项目硬禁令，如：禁全仓自动格式化／UI 变更先改事实源经确认／推送发布必须先取得同意>
- 并行会话：提交一律 `git commit -- <文件级路径>`，勿 `git add -A`／目录级 pathspec；互斥面以 STATUS 当期行为准，他人文件只读不写不提交不回退。
````
